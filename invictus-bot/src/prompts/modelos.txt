# QUÉ ES ESTO Y EN QUÉ SE DIFERENCIA DE catalogo.txt.
#
#   catalogo.txt   los 347 TÍTULOS completos ("Nike Metcon 7 negro blanco
#                  dama/caballero"). Va al prompt de TEXTO, que es el que
#                  conversa y tiene que nombrar producto con precisión.
#
#   modelos.txt    los MODELOS, sin género y sin color ("Nike Metcon 7").
#                  Va al prompt de VISIÓN.
#
# POR QUÉ NO SE LE MANDA A LA VISIÓN LA LISTA COMPLETA. Se le mandaba, y
# se quitó el 22-sep porque costaba ~3.100 tokens EN CADA FOTO contra el
# cupo de 30.000 por minuto de OpenAI — el mismo cupo del que vive el
# cotejo visual. Pero quitarla del todo dejó al modelo de visión sin saber
# qué existe aquí, justo cuando el prompt le exige escribir el término
# "como aparece en los títulos del catálogo".
#
# Esta lista es el término medio: ~640 tokens en vez de 3.100. Y es lo que
# la visión necesita de verdad — que en la tienda hay "New Balance 9060"
# no le hace falta saberlo 17 veces, una por color. De elegir el color se
# encarga el cotejo, que para eso compara la foto.
#
# CÓMO SE HIZO, POR SI HAY QUE REHACERLA: se sacan los títulos del export
# de inventario, se les quitan género y colores, y se queda lo que SIGA
# APARECIENDO LITERALMENTE en algún título. Esa última condición es la que
# importa: si un nombre de aquí no está dentro de un título real, el
# modelo lo escribiría en "buscar" y la búsqueda devolvería cero.
#
# LAS ERRATAS NO SE CORRIGEN. "Adidas Gallangher", "New Balamce 9060",
# "Kirie Irving 4", "Onitsuka Tiguer", "Dolce Gabanna" están así en
# Shopify, y la búsqueda es literal: corregirlas es perder el producto.
# Por eso conviven las dos formas cuando las dos existen.
#
# Las líneas que empiezan con # no se mandan al modelo.
